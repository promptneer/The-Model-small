# 「老仓管」轻量本地仓库智能体 —— 系统架构说明

> 一句话定位：
>
> **小模型只做大脑（语义理解 → 输出鸟语 DSL），脚本负责体力（文件查找、台账读写、检索），调度器负责翻译与把关。**
> 算力目标：RTX5060 8GB 显存本地运行，模型参数 ≤ 3B。



***

## 1. 为什么是「大脑 + 手脚」架构



|             | 大模型直接干活      | 老仓管（模型 + DSL + 脚本）   |
| ----------- | ------------ | -------------------- |
| 遍历文件 / 循环检索 | 慢、贵、容易幻觉路径   | 脚本毫秒级完成，结果确定         |
| 台账增删改       | 模型记不住状态，易编造  | SQLite 事务 + 审计 + 可回滚 |
| 模糊需求理解      | 模型强项         | 模型强项（保留）             |
| 出错影响面       | 一步错步步错，不可追踪  | 原子操作 + 回滚 + 审计日志，可控  |
| 显存 / 内存     | 每步都在模型里跑，占用高 | 模型只算语义，几 KB 文本，占用最低  |

**边界红线（硬约束）：**



* ✅ 模型负责：理解模糊人类语言、判断任务目标、把人话翻译成鸟语 DSL、异常情况判断；

* ❌ 模型不负责：遍历文件、读写台账、循环检索 —— 这些一律交给脚本；

* 🚫 模型输出非 DSL 的自由文本 → 调度器直接拦截（`dsl_parse_failed`），**不执行任何操作**。

## 3. 完整工作链路（一次需求的生命周期）



```
用户：「查台账里有没有防静电手套」
   │
   ▼
[大脑] 收到自然语言，输出鸟语DSL：
   {"dsl_version":"1.0","intent":"查询防静电手套库存",
    "steps":[{"op":"ledger.query",
              "params":{"action":"find","keyword":"防静电手套"},
              "on_error":"abort"}]}
   │
   ▼
[解析器] 提取 JSON → 校验 op 是否注册、参数是否合规、guard 是否满足
   │
   ▼
[调度器] 执行 ledger.query 原子操作
   ├─ 前置校验：schema 校验通过
   ├─ 执行：ledger.find_asset("防静电手套") → SQLite 白名单查询
   ├─ 结果：{matched:1, rows:[{id:8, name:防静电手套, ...}]}
   └─ 记录执行轨迹
   │
   ▼
[大脑] 收到执行结果，整理成自然语言汇报（也可用默认格式化）
   「台账中有 1 条：防静电手套，位于工具间-02柜，共 50 双」
```

## 5. 原子性与容错机制

### 5.1 原子操作定义（核心概念）

> 原子操作（Atom）是鸟语 DSL 的最小执行单元：
> **不可再拆分**
>
> ：一个操作只做一件事；
> **要么完整成功，要么回滚**
>
> ：写操作自带 
>
> `undo`
>
>  信息，失败时调度器逆序回滚；
> **自带前置校验**
>
> ：参数 schema + guard，非法输入在执行前被拦截。

### 5.2 失败策略（on\_error）



| 策略          | 行为                    | 适用           |
| ----------- | --------------------- | ------------ |
| `abort`（默认） | 立即停止，逆序回滚已成功的写操作，整单失败 | 需要严格一致性的多步操作 |
| `continue`  | 记录失败步骤，继续执行后续步骤       | 查询类、可容忍部分失败  |

### 5.3 回滚示例（已通过自测验证）



```
步骤1: ledger.update insert「测试资产」  → 成功（返回 undo={action:delete, id:9}）
步骤2: file.find  root=不存在的目录      → 失败
   └─ 调度器逆序回滚：rollback(步骤1的undo) → 删除 id=9，台账恢复原状
```

### 5.4 拦截矩阵（非法输入全部在执行前拦下）



| 输入                    | 拦截点              | 结果                     |
| --------------------- | ---------------- | ---------------------- |
| 未注册 op（如 `shell.run`） | 解析器              | `dsl_parse_failed`，零执行 |
| 非 JSON 自由文本           | 解析器              | `dsl_parse_failed`，零执行 |
| 参数缺必填 / 类型错 / 超范围     | 调度器 schema 校验    | `guard_failed`，零执行     |
| guard 要求目录 / 文件不存在    | 调度器前置校验          | `guard_failed`，零执行     |
| 台账 SQL 带非白名单表 / 写关键字  | ledger.query 白名单 | 执行失败，不落库               |

## 6. 显存与模型选型



| 部署机               | 模型                    | 量化       | 显存占用（约）  | 说明      |
| ----------------- | --------------------- | -------- | -------- | ------- |
| RTX5060 8GB（推荐）   | Qwen2.5-3B-Instruct   | Q4\_K\_M | \~2.4 GB | 默认；余量充足 |
| RTX5060 8GB（有余量）  | Qwen3-4B / 3B 更高精度    | Q5/Q6    | \~3-4 GB | 可自行升级   |
| GTX1650 4GB（本测试机） | Qwen2.5-1.5B-Instruct | Q4\_K\_M | \~1.2 GB | 真机验证通过  |
| 无 GPU             | 任意 ≤3B Q4             | CPU      | 内存～2GB   | 慢但可用    |

> 模型只处理短文本（需求 + DSL），上下文占用极小；显存大头在模型权重与 KV cache，8GB 跑 3B Q4 余量充足。

## 7. 扩展指南：新增一个原子操作（三步）



1. 在 `atoms/` 新建 `xxx.py`，继承 `core.registry.Atom`：



```
from core.registry import Atom, register
@register
class MyOp(Atom):
    name = "my.op"
    schema = {"type":"object","required":["x"],"properties":{"x":{"type":"string"}}}
    def run(self, ctx, params): ...   # 返回 dict
    def rollback(self, ctx, params, result): ...  # 写操作必须实现
```



1. 在 `atoms/__init__.py` 加一行 `from . import xxx`；

2. 在 `core/dsl_parser.py` 的 `VALID_OPS` 加入 `"my.op"`，并在 `brain.py` 的 system prompt 中登记给模型。

## 8. 已知边界（如实说明）



* 台账为单机 SQLite，无多人并发（仓库内网单机场景够用）；

* mock 大脑仅用于无模型环境验证链路，**不冒充真模型**（界面明确标注）；

* 模型能力受 3B 参数量限制：复杂多轮推理可能不稳定，调度器会在「模型输出非法 DSL」时拦截并请用户重述；

* 文件查找限定目录范围，不跨盘；默认不跟随符号链接（防死循环）。
